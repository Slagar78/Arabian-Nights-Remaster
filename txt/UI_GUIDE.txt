1. ИЗ ЧЕГО СОСТОИТ НАШ UI (Структура файлов)
------------------------------------------------------------------------
- ui.f90          -> Мозг интерфейса. Живут функции ui_button, ui_toggle_simple, ui_draw_text.
- textures.f90    -> texture_draw_9slice (режет картинку на 9 частей при растяжении).
- sdl_bind.f90    -> Привязки к C. Общение с видеокартой и Windows.
- assets/button.png -> Картинка для кнопок (синяя).
- assets/track.png  -> Дорожка (фон) для тумблера (белая или серая).
- assets/thumb.png  -> Кружок (ползунок) для тумблера (белый).


2. КАК ВЫЗВАТЬ ОБЫЧНУЮ КНОПКУ (Одна строчка)
------------------------------------------------------------------------
В игровом цикле пишешь:

    if (ui_button(renderer, btn_tex, X, Y, Ширина, Высота, "Текст")) then
        ! Этот код сработает ТОЛЬКО если игрок кликнул по кнопке!
        print *, "Кнопка нажата!"
    end if

Пример:
    if (ui_button(renderer, btn_tex, 100, 100, 200, 60, "Играть")) then
        call start_game()
    end if

* Цвета (по желанию): последние 6 параметров — это RGB кнопки и текста.
    if (ui_button(renderer, btn_tex, X, Y, W, H, "Удалить", 255, 0, 0, 255, 255, 255)) then ...


3. КАК ВЫЗВАТЬ ТУМБЛЕР (Переключатель Вкл/Выкл)
------------------------------------------------------------------------
Тумблер принимает переменную-состояние (logical). Он сам переключит её 
с .true. на .false., если по нему кликнуть.

    ! Сначала объяви переменную в начале main.f90:
    logical :: sound_on
    sound_on = .true. ! Начальное состояние

    ! В игровом цикле вызываешь тумблер:
    if (ui_toggle_simple(renderer, tex_track, tex_thumb, X, Y, Ширина, Высота, sound_on)) then
        print *, "Тумблер нажат! Теперь состояние: ", sound_on
    end if

Пример с текстом рядом:
    call ui_draw_text(renderer, "Звук", 550, 130, 255, 255, 255) ! Рисуем надпись
    if (ui_toggle_simple(renderer, tex_track, tex_thumb, 650, 120, 80, 40, sound_on)) then
        ! Тут можно включить/выключить звук в игре
    end if


4. ⚠️ ВАЖНО: ЗАЩИТА ОТ ДРЕБЕЗГА (ui_update)
------------------------------------------------------------------------
Игра работает 60 кадров в секунду. Если зажать мышку на 1 секунду, игра 
посчитает это за 60 кликов (тумблер начнет бешено мигать).

Чтобы этого не было, мы запомнили состояние кнопки мыши.
!!! ОБЯЗАТЕЛЬНО !!! Вызывай ui_update() в самом конце каждого кадра:

    do while (running /= 0)
        ! ... твой код (отрисовка, клики) ...
        
        call sdl_render_present(renderer)
        call ui_update()  ! <--- ОБЯЗАТЕЛЬНО СБРАСЫВАЕТ ЗАЩЕЛКУ МЫШИ
    end do


5. КАК НАРИСОВАТЬ ПРОСТО ТЕКСТ (Без кнопки)
------------------------------------------------------------------------
Можно писать текст в любом месте экрана:
    call ui_draw_text(renderer, "Привет, мир!", X, Y, R, G, B)
    call ui_draw_text(renderer, "Металл: 500", 20, 20, 255, 255, 255) ! Белый


6. КАК ЭТО РАБОТАЕТ ВНУТРИ (Магия 9-slice)
------------------------------------------------------------------------
Если растянуть картинку 64x34 до 300x100, то углы скруглений "поплывут".
Функция texture_draw_9slice режет картинку на 9 частей:
- 4 угла (по 12 пикселей) рисует как есть (они не плывут).
- 4 края растягивает только в ОДНОМ направлении.
- Центр растягивает как угодно.
Результат: кнопка ЛЮБОГО размера выглядит идеально.

Тумблер (ui_toggle_simple) использует эту же магию для трека, а кружок 
(thumb) просто двигает влево или вправо, не растягивая его.


7. КАК ПОМЕНЯТЬ ЦВЕТА?
------------------------------------------------------------------------
Цвета задаются в формате RGB от 0 до 255. 
Для кнопок они необязательные. Если не писать — будет оригинал.
    ! КРАСНАЯ кнопка (255, 50, 50) с ЖЕЛТЫМ текстом (255, 255, 0)
    if (ui_button(renderer, btn_tex, X, Y, W, H, "Опасно", 255, 50, 50, 255, 255, 0)) then ...

ВАЖНО: Файл ui.f90 должен быть сохранен в кодировке UTF-8, чтобы 
русские буквы не превратились в кракозябры на экране.

8. ⏱️ ФИКСИРОВАННЫЙ ШАГ (60 FPS) И ТАЙМЕР
------------------------------------------------------------------------
Раньше игра зависела от частоты монитора (на 144 Гц персонаж бегал в 2.4 раза 
быстрее). Теперь у нас есть модуль `timer.f90`, который жестко привязывает 
логику к 60 кадрам в секунду (как на старых консолях Sega/SNES).

* ВАЖНО: В игровом цикле (main.f90) логика игры (игрок, камера, коллизии) 
  должна вызываться ТОЛЬКО внутри проверки `if (timer_update()) then`.
* Интерфейс (кнопки, тумблеры) и `ui_update()` вызываются КАЖДЫЙ кадр 
  (вне блока timer_update), чтобы мышь работала отзывчиво и плавно.

Пример правильного игрового цикла:
    if (timer_update()) then
        call player_update(keys)
        call camera_set_target(px, py, moving)
        call camera_update()
    end if
    ! ... отрисовка карты, игрока и UI ...
    call sdl_render_present(renderer)
    call ui_update()


9. 🔢 ЦЕЛОЧИСЛЕННАЯ МАТЕМАТИКА (PIXEL-PERFECT)
------------------------------------------------------------------------
Мы полностью отказались от дробных чисел (`real`, `float`) для координат.
Все координаты игрока (`px`, `py`), смещение (`pixel_offset`) и камера 
(`cam_x`, `cam_y`) — это строго **integer (целые числа)**.

Зачем это нужно:
- Если использовать дроби (например, 10.5 пикселя), SDL2 округляет их при 
  отрисовке. Из-за этого спрайты начинают "дрожать" (jitter), когда сдвигаются 
  то на 1, то на 2 пикселя.
- Целые числа гарантируют идеальную, четкую пиксельную картинку, как на CRT-телевизорах.
- В коде отрисовки (`player.f90`, `map.f90`) больше нет `int()` или `nint()`. 
  Мы просто вычитаем `cam_x` из `px`: `dst_rect%x = px - cam_x`.

Скорость движения (`PLAYER_SPEED`) задается в пикселях за кадр. 
Например, `PLAYER_SPEED = 6` означает 360 пикселей в секунду при 60 FPS.
