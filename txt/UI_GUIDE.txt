1. ИЗ ЧЕГО СОСТОИТ НАШ UI (Структура файлов)
------------------------------------------------------------------------
- ui.f90          -> Мозг интерфейса. Живут функции ui_button, ui_toggle_simple, ui_draw_text.
- textures.f90    -> texture_load, texture_draw_9slice (9-slice),
                     texture_draw (вся текстура), texture_draw_part (вырезка),
                     texture_draw_part_ex (вырезка + flip).
                     ⚠️ См. раздел 10 — почему НЕЛЬЗЯ рисовать напрямую.
- sdl_bind.f90    -> Привязки к C. Общение с видеокартой и Windows.
- assets/button.png -> Картинка для кнопок (синяя).
- assets/track.png  -> Дорожка (фон) для тумблера (белая или серая).
- assets/thumb.png  -> Кружок (ползунок) для тумблера (белый).


2. КАК ВЫЗВАТЬ ОБЫЧНУЮ КНОПКУ (Одна строчка)
------------------------------------------------------------------------
В игровом цикле пишешь:

    if (ui_button(renderer, btn_tex, X, Y, Ширина, Высота, "Текст")) then
        ! Этот код сработает ТОЛЬКО если игрок кликнул по кнопке!
        print *, "Кнопка нажата!"
    end if

Пример:
    if (ui_button(renderer, btn_tex, 100, 100, 200, 60, "Играть")) then
        call start_game()
    end if

* Цвета (по желанию): последние 6 параметров — это RGB кнопки и текста.
    if (ui_button(renderer, btn_tex, X, Y, W, H, "Удалить", 255, 0, 0, 255, 255, 255)) then ...

⚠️ ВАЖНО (hover-эффект): внутри ui_button при наведении мыши
   к цвету кнопки прибавляется +40 (clamp до 255). Поэтому:
   - Кнопка с цветом (255, 100, 100) → при hover станет (255, 140, 140) — ВИДНО.
   - Кнопка БЕЗ явного цвета (255, 255, 255) → hover НЕ ВИДЕН (255+40 = 255).
   Если нужен видимый hover — задавай базовый цвет не белым,
   например (200, 200, 200), или передавай btn_r/g/b явно.


3. КАК ВЫЗВАТЬ ТУМБЛЕР (Переключатель Вкл/Выкл)
------------------------------------------------------------------------
Тумблер принимает переменную-состояние (logical). Он сам переключит её 
с .true. на .false., если по нему кликнуть.

    ! Сначала объяви переменную в начале main.f90:
    logical :: sound_on
    sound_on = .true. ! Начальное состояние

    ! В игровом цикле вызываешь тумблер:
    if (ui_toggle_simple(renderer, tex_track, tex_thumb, X, Y, Ширина, Высота, sound_on)) then
        print *, "Тумблер нажат! Теперь состояние: ", sound_on
    end if

Пример с текстом рядом:
    call ui_draw_text(renderer, "Звук", 550, 130, 255, 255, 255) ! Рисуем надпись
    if (ui_toggle_simple(renderer, tex_track, tex_thumb, 650, 120, 80, 40, sound_on)) then
        ! Тут можно включить/выключить звук в игре
    end if


4. ⚠️ ВАЖНО: ЗАЩИТА ОТ ДРЕБЕЗГА (ui_update)
------------------------------------------------------------------------
Игра работает 60 кадров в секунду. Если зажать мышку на 1 секунду, игра 
посчитает это за 60 кликов (тумблер начнет бешено мигать).

Чтобы этого не было, мы запомнили состояние кнопки мыши.
!!! ОБЯЗАТЕЛЬНО !!! Вызывай ui_update() в самом конце каждого кадра:

    do while (running /= 0)
        ! ... твой код (отрисовка, клики) ...
        
        call sdl_render_present(renderer)
        call ui_update()  ! <--- ОБЯЗАТЕЛЬНО СБРАСЫВАЕТ ЗАЩЕЛКУ МЫШИ
    end do


5. КАК НАРИСОВАТЬ ПРОСТО ТЕКСТ (Без кнопки)
------------------------------------------------------------------------
Можно писать текст в любом месте экрана:
    call ui_draw_text(renderer, "Привет, мир!", X, Y, R, G, B)
    call ui_draw_text(renderer, "Металл: 500", 20, 20, 255, 255, 255) ! Белый


6. КАК ЭТО РАБОТАЕТ ВНУТРИ (Магия 9-slice)
------------------------------------------------------------------------
Если растянуть картинку 64x34 до 300x100, то углы скруглений "поплывут".
Функция texture_draw_9slice режет картинку на 9 частей:
- 4 угла (по 12 пикселей) рисует как есть (они не плывут).
- 4 края растягивает только в ОДНОМ направлении.
- Центр растягивает как угодно.
Результат: кнопка ЛЮБОГО размера выглядит идеально.

Тумблер (ui_toggle_simple) использует эту же магию для трека, а кружок 
(thumb) просто двигает влево или вправо, не растягивая его.


7. КАК ПОМЕНЯТЬ ЦВЕТА?
------------------------------------------------------------------------
Цвета задаются в формате RGB от 0 до 255. 
Для кнопок они необязательные. Если не писать — будет оригинал.
    ! КРАСНАЯ кнопка (255, 50, 50) с ЖЕЛТЫМ текстом (255, 255, 0)
    if (ui_button(renderer, btn_tex, X, Y, W, H, "Опасно", 255, 50, 50, 255, 255, 0)) then ...

ВАЖНО: Файл ui.f90 должен быть сохранен в кодировке UTF-8, чтобы 
русские буквы не превратились в кракозябры на экране.

8. ⏱️ ФИКСИРОВАННЫЙ ШАГ (60 FPS) И ТАЙМЕР
------------------------------------------------------------------------
Раньше игра зависела от частоты монитора (на 144 Гц персонаж бегал в 2.4 раза 
быстрее). Теперь у нас есть модуль `timer.f90`, который жестко привязывает 
логику к 60 кадрам в секунду (как на старых консолях Sega/SNES).

* ВАЖНО: В игровом цикле (main.f90) логика игры (игрок, камера, коллизии) 
  должна вызываться ТОЛЬКО внутри проверки `if (timer_update()) then`.
* Интерфейс (кнопки, тумблеры) и `ui_update()` вызываются КАЖДЫЙ кадр 
  (вне блока timer_update), чтобы мышь работала отзывчиво и плавно.

Пример правильного игрового цикла:
    if (timer_update()) then
        call player_update(keys)
        call camera_set_target(px, py, moving)
        call camera_update()
    end if
    ! ... отрисовка карты, игрока и UI ...
    call sdl_render_present(renderer)
    call ui_update()

* Известное ограничение: `if (timer_update())` делает ОДИН шаг логики,
  даже если прошло больше 1/60 секунды (на слабом железе или при лагах
  игра замедлится, а не «догонит»). Для JRPG это приемлемо. Если понадобится
  «догоняющая» логика — заменить `if` на `do while (timer_update()) ... end do`.


9. 🔢 ЦЕЛОЧИСЛЕННАЯ МАТЕМАТИКА (PIXEL-PERFECT)
------------------------------------------------------------------------
Мы полностью отказались от дробных чисел (`real`, `float`) для координат.
Все координаты игрока (`px`, `py`), смещение (`pixel_offset`) и камера 
(`cam_x`, `cam_y`) — это строго **integer (целые числа)**.

Зачем это нужно:
- Если использовать дроби (например, 10.5 пикселя), SDL2 округляет их при 
  отрисовке. Из-за этого спрайты начинают "дрожать" (jitter), когда сдвигаются 
  то на 1, то на 2 пикселя.
- Целые числа гарантируют идеальную, четкую пиксельную картинку, как на CRT-телевизорах.
- В коде отрисовки (`player.f90`, `map.f90`) больше нет `int()` или `nint()`. 
  Мы просто вычитаем `cam_x` из `px`: `dst_rect%x = px - cam_x`.

Скорость движения (`PLAYER_SPEED`) задается в пикселях за кадр. 
Например, `PLAYER_SPEED = 6` означает 360 пикселей в секунду при 60 FPS.

10. 🎨 КАК РИСОВАТЬ ТЕКСТУРЫ (и почему НЕ напрямую)
------------------------------------------------------------------------
В SDL2 функция `SDL_SetTextureColorMod` — это НЕ параметр вызова, а
СОСТОЯНИЕ текстуры. Оно запоминается внутри объекта и живёт, пока его
не перезапишут. Это значит:

    call sdl_set_texture_color_mod(tex%ptr, 255, 100, 100)   ! сделали красным
    call sdl_render_copy(renderer, tex%ptr, ...)              ! нарисовали красным
    ! ... 200 строк кода спустя ...
    call sdl_render_copy(renderer, tex%ptr, ...)              ! ⚠️ ОПЯТЬ КРАСНЫМ!

Никакого «сброса при следующем вызове» нет. Поэтому в textures.f90
сделана двухуровневая защита.

--- УРОВЕНЬ 1: сброс в texture_draw_9slice ------------------------------
В конце texture_draw_9slice автоматически ставится (255, 255, 255) —
нейтральное состояние (умножение на 1.0 = без изменений). Это правило
«кто занял состояние — тот его и вернул».

--- УРОВЕНЬ 2: обёртки, которые ВСЕГДА ставят нейтральный цвет ---------
Три функции-обёртки в textures.f90. ВСЕГДА используй их вместо
прямого `sdl_render_copy` / `sdl_render_copy_ex` для `type(texture_t)`:

    ! Вся текстура целиком (src = NULL). Для кнопок, портретов, рамок, thumb.
    subroutine texture_draw(tex, renderer, dst)

    ! Вырезка из атласа (src). Для тайлов, спрайтов, кристаллов.
    subroutine texture_draw_part(tex, renderer, src, dst)

    ! Вырезка с отражением по горизонтали. Для Шукран влево, flip-анимаций.
    subroutine texture_draw_part_ex(tex, renderer, src, dst, flip)

Примеры:

    ! Портрет в меню (вся текстура)
    type(sdl_rect) :: dst
    dst%x = 350; dst%y = 226; dst%w = 192; dst%h = 256
    call texture_draw(portrait_tex, renderer, dst)

    ! Спрайт из атласа (вырезка)
    type(sdl_rect) :: src, dst
    src%x = 0; src%y = 0; src%w = 64; src%h = 128
    dst%x = px - cam_x; dst%y = py - cam_y
    call texture_draw_part(shukran_tex, renderer, src, dst)

    ! Спрайт с отражением (Шукран идёт влево)
    call texture_draw_part_ex(shukran_tex, renderer, src, dst, SDL_FLIP_HORIZONTAL)

--- ГДЕ МОЖНО ОСТАВИТЬ прямой sdl_render_copy -------------------------
Единственное место, где допустимо рисовать напрямую — временные текстуры
из `type(c_ptr)`, а не `type(texture_t)`. Например, текст в ui_draw_text:

    txt_tex = sdl_create_texture_from_surface(renderer, txt_surf)
    call sdl_render_copy(renderer, txt_tex, c_null_ptr, dst)  ! ✅ ОК
    call sdl_destroy_texture(txt_tex)

Здесь `txt_tex` создаётся «здесь и сейчас» с ColorMod = (255,255,255)
по умолчанию и сразу уничтожается. Утечки быть не может. Обёртка не нужна.


11. ⚠️ ЧЕК-ЛИСТ: КАК ПРОВЕРИТЬ, ЧТО ЦВЕТ НЕ «ПРОТЁК»
------------------------------------------------------------------------
Если добавил новую отрисовку и видишь, что какая-то текстура стала
странного цвета (красная, синяя, потемневшая) без твоего желания:

1. Найди в своём коде вызов `sdl_set_texture_color_mod(...)`.
2. Проверь, что после него в ТОЙ ЖЕ функции стоит сброс:
       call sdl_set_texture_color_mod(tex%ptr, 255, 255, 255)
   или что ты рисуешь через `texture_draw*` (они сбрасывают сами).
3. Проверь, что ты не вызываешь `sdl_render_copy` напрямую для
   `type(texture_t)` — замени на `texture_draw` / `texture_draw_part`.

Правило на будущее:
    «Кто меняет состояние — тот его и восстанавливает.»
    «Не доверяй никому — перед рисованием ставь известное состояние.»

Если добавляешь новую функцию, которая меняет ColorMod (например,
`texture_draw_rotated` или `texture_draw_tinted`) — ОБЯЗАТЕЛЬНО
сбрось в (255,255,255) в конце. Или используй `texture_draw*` внутри.


12. 🖨️ КРАКОЗЯБРЫ В КОНСОЛИ (print *)
------------------------------------------------------------------------
Симптом: в консоли MSYS2 UCRT64 при запуске `make run` вместо
«=== ЗАГРУЗКА: cairo ===» видишь «=== ╨Ч╨Р╨г╨а╨г╨Ч╨Ъ╨Р: cairo ===».

Причина: Fortran-файлы сохранены в UTF-8 (обязательное требование),
`print *` выдаёт UTF-8-байты, а консоль Windows по умолчанию использует
CP866. Отсюда кракозябры.

ВАЖНО: на саму игру это НЕ влияет. SDL рисует текст через
TTF_RenderUTF8_Blended, который корректно интерпретирует UTF-8 —
в окне игры всё отображается правильно. Проблема только в консоли.

Решение: в Makefile в цели `run` вместо

    ./app.exe

написать

    cmd //c "chcp 65001 >nul & app.exe"

`chcp 65001` переключает кодовую страницу консоли на UTF-8, `>nul`
глушит служебное сообщение «Active code page: 65001», `&` —
разделитель команд, `app.exe` запускается уже с UTF-8.
`//c` — это MSYS2-трюк, чтобы `/c` не превратился в путь `C:\`.

Если `cmd //c` не работает (редко, на старых MSYS2) — альтернатива:

    @chcp.com 65001 >/dev/null 2>&1 || true
    ./app.exe

⚠️ В Makefile перед этими строками должна быть НАСТОЯЩАЯ табуляция
(Tab), не пробелы. Иначе будет ошибка `missing separator`.
